# GUI Front-End

The Avalonia front-end (`Hst.Commander.Gui`). Read this when changing GUI behavior. What each feature does is in the feature docs; this covers how the GUI does it.

Paths are relative to `src/`. Part of the agent docs, see [`src/agents.md`](../src/agents.md).

## Files

- `MainWindow.axaml(.cs)`: the dual-pane window, menus, function key bar, window-level keys and error display.
- `PaneView.axaml(.cs)`, `PaneView.DragDrop.cs` (see [Drag and drop](#drag-and-drop)): one pane: path panel, column header, entry `ListBox` (list or thumbnails), `IconLayoutView` for plugin navigation modes, the icon positions bar and the listing progress (an indeterminate progress bar with "Reading ..." shown when listing takes longer than `ListingProgress.Delay`, 2 seconds, and, with a progress bar and a Cancel button, when making a temporary copy takes as long through `NavigationContext.ProgressIndicator`; the message is shortened to the pane's width with `PathText.ShortenMessage`, measured with `FormattedText`, keeping the end of a long path like the path panel, e.g. "Reading ...\games\whdload...", and fitted again when the pane is resized).
- `PaneNavigationMode.cs`, `IconLayoutView.cs`: navigation modes, see [Navigation modes](icons-and-navigation-modes.md#navigation-modes).
- `EntryItem.cs`: a display row for an `IEntry`.
- `WindowsVirtualFileDrag` (in Core, as the TUI uses it for the clipboard), `MacOS/MacFilePromiseDrag.cs`: dragging entries of images and other volumes out as virtual files and file promises, see [Drag and drop](#drag-and-drop).
- `TaskbarProgress.cs`, `Windows/WindowsTaskbarProgress.cs`, `MacOS/MacDockProgress.cs`: the progress of file operations on the taskbar button and Dock tile, see [Taskbar progress](#taskbar-progress). `MacOS/ObjC.cs`: the Objective-C runtime calls shared by the macOS interop.
- `Icons/`: `FileIcons` (loading and caching entry icons), `IFileIconProvider` with Windows, freedesktop and macOS implementations, and `ViewerIcon` for the icon viewer.
- `ViewerDialog` with `ViewerControl` and `ViewerSearchDialog`: the viewer.
- `ThemeManager.cs`, `GuiFonts.cs`, `FontDownloadDialog.axaml(.cs)`, `ThemeChromeStyles.axaml`, `GuiSettings.cs`: themes, fonts (including downloading a theme's font) and settings.
- `BackgroundPicker`: the background chooser shared by the icon viewer and the image view.
- Dialogs, one `.axaml` each: `ErrorDialog`, `SettingsDialog`, `EditorDialog` (+ `EditorSearchDialog`, `GoToLineDialog`, `SaveChangesDialog`), `ExternalEditDialog`, `CopyDialog`, `CopyProgressDialog`, `OverwriteDialog`, `DeleteDialog`, `DeleteProgressDialog`, `QuitDialog`, `ConfirmDialog` (a question with two buttons or a message, e.g. restarting as administrator), `MakeDirectoryDialog`, `CreateVolumeDialog`, `CreateVolumeFieldsDialog`, `SelectGroupDialog`, `PropertiesDialog`, `IconViewerDialog`, `VolumeProviderDialog`, `BookmarksDialog` (the bookmark list of the Bookmarks item), `BookmarkDialog` (the description of a new bookmark), `EditBookmarkDialog` (the description, location, path, user name and stored password of a bookmark; invalid input shown below the fields), `LocationDialog`, `VolumeLocationDialog` (the location of a volume provider asking for one, e.g. an SMB path), `CredentialsDialog` (user name and password, the password hidden with `PasswordChar`), `ConnectionDialog` (the protocol as a `ComboBox`, host, port with the default port as placeholder text, path, user name and password of a volume provider asking for connection details, e.g. FTP/SFTP; invalid input shown below the fields), `AboutDialog` (+ `LicenseDialog`, a read-only text box with a license notice).

## Avalonia

- Avalonia 12 with the Fluent theme and plain code-behind (no MVVM framework).
- `Program.Main` has `[STAThread]` (not top-level statements, which run the main thread as MTA): Avalonia only uses OLE on an STA UI thread on Windows, and without OLE windows don't accept drops and dragging out fails.
- Most keys (function keys, Tab, `+`/`-`/`*`, Ctrl+A, Ctrl+D, Ctrl+L, Ctrl+H, Ctrl+B, Ctrl+S, Ctrl+F, Ctrl+R, Ctrl+U, Ctrl+P/Alt+Enter, Ctrl+Z (the [command palette](command-palette.md), only in the panes so text boxes keep undo), the volume provider keys, Ctrl+1-9, and Ctrl+T and Ctrl+Enter of the [command line](command-line.md#gui)) are handled at window level with tunnelling `KeyDown` handlers. Enter (without Ctrl), Backspace, Ctrl+PageDown and Ctrl+\ are handled with a tunnelling handler on the list.
- The volume provider and create volume lists handle Enter with a tunnelling handler on the list, because the focused list item takes Enter before the default OK button sees it.
- `+`, `-` and `*` are matched by `KeySymbol` (plus `Key.Add`/`Subtract`/`Multiply`) and shown in the menu headers, because key gestures would display as `OemPlus`. Ctrl+\ matches the `\` or `<` symbol, `Key.OemPipe`, `Key.OemBackslash` or the physical `Backslash` and `IntlBackslash` keys, so the key left of Z works on layouts where it's `<` (e.g. Danish, where `\` needs AltGr or Option). On macOS also `PhysicalKey.Backquote`: on ISO Mac keyboards macOS reports the key left of Z with the key code of the US `` ` `` key (so Ctrl+`` ` `` on a US Mac goes to the root too).
- Dialogs are shown with `ShowDialog(owner)`. Progress dialogs (copy/move, delete) start the operation with `Task.Run` when opened and report through a `Progress<T>` created on the UI thread; questions such as overwriting are shown over them with `Dispatcher.UIThread.InvokeAsync`. Closing the window cancels, and the dialog closes when the operation has stopped and exposes its `Exception`.
- Dialogs opening on a button (e.g. Yes in the delete and overwrite questions) focus it with `DialogButtons.Focus`, which uses `NavigationMethod.Tab`: a plain `Focus()` doesn't set `:focus-visible`, so no focus ring showed which button had the focus. Left and Right move the focus between the buttons of a row, wrapping around, with a tunnelling class handler on every `Window` (`DialogButtons.Register`, called at startup); Enter presses the focused button.
- Errors are raised as `PaneView.NavigationFailed` and shown by `MainWindow` with `ErrorDialog`, which logs them with their exception (see [Errors and crash reports](application.md#errors-and-crash-reports)); `ErrorDialog.Notice` shows messages that aren't failures (e.g. an action the location doesn't support) without logging them. Unhandled exceptions on the UI thread are shown with `UnexpectedErrorDialog`. `PaneView.CreateVolumeAsync` throws instead, so the error is shown before asking again.
- `ErrorDialog` shows a red error icon left of the message, and dialogs asking a question (`ConfirmDialog`, `QuitDialog`, `SaveChangesDialog`, `DeleteDialog`, `OverwriteDialog`) show a blue question mark icon (`QuestionIcon`) left of the question; both are vector drawings, the same in all themes. A `ConfirmDialog` without a no button only shows a message and hides the icon.
- The function key bar buttons aren't focusable, so the active pane keeps the focus.

## Panes

- The columns are those of the pane's `NavigationContext.Columns` (`PaneView.Columns`, see [Pane columns](file-operations.md#pane-columns)). `PaneView.UpdateColumns` creates the header and the dividers in code; the rows' `EntryRowCells` (a `Grid` styled as one) creates the cells for the columns of its `EntryItem` (`EntryItem.Columns` and `Texts`, read when the entries are listed), keeping the name cell with the icon from the template, and follows its data context, as rows are reused. Widths of the columns but Name are resources of the pane (`PaneView.GetColumnWidthKey`) bound by the header, dividers and rows, so they line up and scale with the font.
- The name column fills the remaining width and is trimmed with an ellipsis. Column dividers are a non-hit-testable grid behind the list, so they continue below the last entry.
- The path panel keeps its height when the marked summary and disk space are empty.
- The `ListBox` isn't focusable and arrow keys only move the selection while an item has focus, so `PaneView.FocusEntries` focuses the selected item's container (realizing it with `UpdateLayout` if needed). The left pane has the focus on startup; Tab always switches panes.
- Ctrl+R (Go > Refresh) lists the active pane again. Ctrl+U (Go > Swap panes) swaps the panes' contents with `PaneView.SwapWithAsync` (navigation context, entries, cursor and navigation mode, as `LeftPane`/`RightPane` are fixed controls) and saves the navigation modes for their new sides; the focus moves to the other side, with the active pane's contents.
- **Quick search** (Ctrl+F, see [Quick search](file-operations.md#quick-search)): `QuickSearchBar` is a border with a text block in a row of its own below the entries (an overlay covered the entry found at the bottom of the list; the current entry is scrolled into view after the list gets shorter), not a text box, so the list item keeps the focus. While it's active, the window's tunnelling `KeyDown` calls `PaneView.HandleQuickSearchKey` first, before `+`/`-`/`*`, Tab, Del and the other window keys. Backspace, Up, Down, Ctrl+F and Esc are handled there. Keys typing a character are left unhandled, and the list's `KeyDown` skips them too, so Space doesn't mark. The character then arrives as `TextInput`, handled with a tunnelling handler on the list and the icon layout. AltGr characters (Ctrl+Alt) count as typed. Bare modifier keys are ignored, so Shift works for upper case. Commands > Quick search starts it with `Dispatcher.UIThread.Post`, after the menu has given the focus back. Losing the focus is checked after the pending focus changes (also posted), because moving to an entry further away recycles the focused row's container, so the focus leaves the list for a moment and the first typed character stopped the quick search.
- PageUp/PageDown and Home/End are handled in `PaneView`, because the list's `ScrollViewer` would otherwise only scroll the view without moving the selection.
- The current row is only shown in the active pane: `MainWindow.SetActivePane` sets `PaneView.IsActive`, which adds the `active` class; rows of the other list have no selection background in any theme.
- Row classes: `executable` (green) comes before the current-row and `marked` (yellow) styles, so marked entries stay yellow under the cursor.
- Icons: see [GUI icons](icons-and-navigation-modes.md#gui-icons).
- **Context menu** (`PaneView.ContextMenu.cs`): Copy, Cut, Paste, Rename, Delete, PowerShell here, Terminal here, Command prompt here and Properties, on the list, thumbnails and the icons of plugins' navigation modes. Right-clicking an entry makes it the current entry first (`OnEntriesPointerPressed` with the right button, `IconLayoutView.ItemRightClicked`); right-clicking below the entries clears the cursor, so only Paste is enabled. The menu acts on the marked entries like the function keys. The menu key, Shift+F10 and Ctrl+F10 open it below the current entry when released and close it when pressed again: Avalonia does this itself (`Control.OnKeyUp` raises `ContextRequested` for the keys of `HotkeyConfiguration.OpenContextMenu`, and the open menu closes on the same keys' key-up), so the window only stops Shift+F10 and Ctrl+F10 from reaching F10 (quit). Avalonia only has Shift+F10 there on Windows, so `App.AddContextMenuKeys` adds Shift+F10 and Ctrl+F10 on every system (Ctrl+F10 like the TUI). Opening it on key down made the key-up close it again. Items raise `PaneView.ActionRequested`, which `MainWindow` runs with `RunActionAsync` on that pane. PowerShell here, Terminal here and Command prompt here (`ShellHere` in Core, only Terminal here on macOS and Linux) raise `PaneView.ShellHereRequested` and open the shell in the pane's directory without waiting for it, enabled only in local directories (`NavigationContext.CurrentHostDirectory`, like the command line): PowerShell is pwsh when installed, otherwise Windows PowerShell; the command prompt is `ComSpec`; the terminal is Windows Terminal (`wt.exe -d`) on Windows, Terminal (`open -a Terminal`) on macOS and `TERMINAL` or the first terminal emulator found on Linux (`ShellHere.LinuxTerminals`). The TUI has them too (see [TUI](tui.md)).
- Ctrl+C, Ctrl+X and Ctrl+V are only handled while a pane has the focus (not a text box); see [Clipboard](file-operations.md#clipboard) and `GuiClipboard`. A `DispatcherTimer` lists the panes again when cut files were moved by another application (`EntryClipboard.CheckCutMoved`).

## Drag and Drop

The TUI has no drag and drop: terminals can't drag files out, and dropping only types the path in some terminals.

- **Dragging out:** in the list and thumbnail modes, dragging an entry with the left button (after moving 4 pixels) drags the marked entries when it's marked, otherwise just that entry (".." can't be dragged). Local entries are dragged as their files (`NavigationContext.GetLocalPaths`) with copy and move allowed. When another application moves them (e.g. Explorer with Shift), both panes are listed again.
- **Entries in images and other volumes** (archives, Amiga images, SMB, physical disks) aren't copied first: the drag starts at once and the application dropped on reads them through `VolumeDragSource`, which opens the pane's location again on the thread pool (so the pane can keep navigating) and gives them the names and UAE metadata copying to a local directory gives them with the UAE metadata setting (see [UAE metadata](file-operations.md#uae-metadata)): the metadata files (`_UAEFSDB.___` or `.uaem`) are made in memory for each dragged directory and dragged after its entries, metadata files of the source aren't dragged, and with `None` entries get local names (e.g. `file_1` for the Amiga name `file*1`). Dropped in a directory that already has a `_UAEFSDB.___` file, Explorer asks to replace it rather than adding to it.
  - **Windows** (`WindowsVirtualFileDrag` in Core): virtual files in an OLE data object of our own run with `SHDoDragDrop`, because Avalonia's drag source only offers data in memory. "FileGroupDescriptorW" lists the files and directories, "FileContents" gives a stream per file and "Preferred DropEffect" asks for a copy. The data object supports `IDataObjectAsyncCapability`, so Explorer copies after the drop with its own progress dialog. Explorer's calls arrive on the UI thread, so reads run on the thread pool and are waited for. The drag source is closed once the drag has ended, Explorer has finished copying (`EndOperation`) and every stream it was given has been read to its end (reading again at the end reads no bytes, as Explorer reads until it gets none, and seeking only moves the position the next read goes to, as Explorer seeks after reading the end); a drag whose files stopped being read (e.g. cancelled) is closed when the next drag starts. Explorer always copies (a move with Shift doesn't delete anything in the volume).
  - **macOS** (`MacOS/MacFilePromiseDrag.cs`): file promises (`NSFilePromiseProvider`) in a dragging session of our own on the window's `NSView` (`IMacOSTopLevelPlatformHandle`), with the delegate and dragging source registered as Objective-C classes through the Objective-C runtime. Finder asks for each dragged entry to be written where it was dropped (`VolumeDragSource.CopyToLocalAsync`, on an operation queue), copied there with UAE metadata like copying; the entry gets the promised name (its local name) unless it has UAE metadata, which refers to the name copying gave it.
  - **Linux:** no file manager reads such files, so these entries are only dragged to the panes.
  - Errors reading the entries are shown when the drop target reads them.
- **Dropping** on a pane, from either pane or another application, copies, or moves with Shift. A drag of another application is taken whatever action it allows (`GetDragOverEffect`): on Linux, X11 drag and drop (Avalonia's XDND, also with Wayland apps through XWayland) suggests a single action, e.g. move from Ubuntu's Files, or none for "ask", which a pane wanting copy refused. In the list and thumbnails, dropping on a directory row copies into that directory (the row is outlined), otherwise into the current location (the pane is outlined). In the plugins' navigation modes (e.g. the Workbench, whose icons are dragged to move them), entries can only be dropped. The drive list only takes drops on a drive. A pane's own entries are only dropped on one of its other directories.
- A drop opens the copy or move dialog with the destination filled in, like F5/F6 (`MainWindow.DropAsync`): entries of a pane through `CopyAsync`/`MoveAsync` of their pane, local files through `DroppedEntries`. A drop always reports the copy effect to the application dragged from, because Explorer would delete the files of a move itself while Hst Commander still asks.
- Entries dragged from a pane travel in an in-process data format (`PaneDragFormat`) next to the files, so a drop on a pane copies them like F5. A drag of the operating system (virtual files, file promises) doesn't carry Avalonia's in-process data, so the dragged entries are kept in `s_nativePaneDrag` while it runs. Drops are handled after the drag has ended (`Dispatcher.UIThread.Post`), so the dialogs aren't opened inside the drag of the operating system.

## Taskbar Progress

The copy, move and delete progress dialogs show their progress outside the window too (see [Common rules](file-operations.md#common-rules)). Avalonia has no API for it (it uses `ITaskbarList3` only internally), so `TaskbarProgress.Create` picks a platform `ITaskbarProgress` when the dialog opens:

- **Windows** (`Windows/WindowsTaskbarProgress.cs`): the shell's `ITaskbarList3` (`SetProgressState`, `SetProgressValue`) on the main window's handle, the dialog's owner, because the taskbar button belongs to it. The taskbar list is created once; when it can't be (e.g. without Explorer) nothing is shown.
- **macOS** (`MacOS/MacDockProgress.cs`): the app icon with a rounded bar along its bottom (blue, yellow when paused, red on errors, empty while indeterminate) is drawn into an `NSImage` and set with `setApplicationIconImage:`, which the Dock shows; clearing sets it to nil, so the default icon (the bundle's) is shown again. A Dock tile content view with an `NSProgressIndicator` showed no bar, because the Dock tile draws its content view into an image and the progress indicator draws in its own layer. The icon is drawn from the app's `.ico` resource, because `applicationIconImage` is a folder icon when the app isn't run from its bundle (e.g. `dotnet run`).
- **Linux:** nothing is shown.

## Viewer

- `ViewerControl` draws with `FormattedText` in a monospace font in the pane brushes, and the selection with `ViewerSelectionBackground`/`Foreground`. It captures the pointer while selecting and has a Copy/Select all context menu. Copying uses the window's `Clipboard`.
- The scroll bars are a vertical one for the position in the file (0-1000) and a horizontal one for text columns. In the image view: zoom buttons and a zoom combo box, a `BackgroundPicker` (the theme's background by default, not remembered) and a list of the file's images; Ctrl+mouse wheel zooms. See [Images in the viewer](viewer.md#images).

## Properties and Icon Viewer

- `PropertiesDialog` shows the entry icon (loaded in the dialog's pixel size; for several entries of one type the type icon) and, in the General tab, `SelectableTextBlock` values, so paths can be copied. The tabs of plugins are `PropertiesTabView`s. The tabs use the `DialogTabItem` theme and `dialogTabs` class of `App.axaml`, shared with `SettingsDialog`.
- Clicking the icon opens `IconViewerDialog` with all icons of the entry: the plugin icon file's icons, otherwise the icons contained in the file, otherwise the OS icon in the distinct sizes the OS returns, otherwise the built-in icon. Images are fitted or zoomed on a selectable background; icons up to 256 pixels are scaled without smoothing so pixels stay sharp. `ViewerIcon` bitmaps are created only when shown.

## Themes and Settings

- Themes: Midnight Commander (default), Light and Dark, the included and user JSON themes and the themes of plugins (see [Themes](themes.md)), chosen from a combo box sorted by name. Each gets a `ThemeVariant` of its own from `ThemeManager`, inheriting Light or Dark. The built-in themes only color the panes (`systemChrome`); menus, the function key bar and dialogs use the normal Fluent styling. Other themes also get `ThemeChromeStyles` for the menu bar, bottom area and buttons, and dialogs in their dialog colors (see [Themes](themes.md#theme-model)).
- The bottom area is a `ButtonPanelView` showing the theme's buttons (the function key bar for the built-in themes). `MainWindow.ApplyAppearance` sets it, the panes' parent buttons and the font. The settings dialog gets a preview callback (`ApplyAppearance`) so the bottom area, parent buttons and font change live too.
- Font: Settings > Appearance chooses the font family (from the installed fonts, `FontManager.Current.SystemFonts`, which Avalonia lists on Windows, macOS and Linux) and size of the panes and the bottom area, stored as `FontFamily` and `FontSize` in `gui-settings.json` (null for the default). `GuiFonts.Resolve` uses the chosen font, otherwise the theme's font when one of its fonts is installed (`ITheme.FontFamily` with its `FontSize`), otherwise the monospace fonts `Cascadia Mono, Consolas, Menlo, DejaVu Sans Mono` at 14. The default fonts stay as fallbacks, and the columns of the panes scale with the font size (`PaneView.UpdateColumnWidths`). Dialogs, the viewer and the editor keep their own fonts. Fonts in `~/.hst-commander/fonts` (downloaded for a theme, see [Fonts](themes.md#fonts)) are loaded at startup and listed like installed fonts.
- Pane colors are per-theme brushes `ThemeManager` adds to the application's `ThemeDictionaries`, referenced with `DynamicResource` so theme changes apply live.
- The settings dialog groups the settings in a `TabControl`: Appearance (theme, font, font size and `Window: Start maximized`, `GuiSettings.StartMaximized`: the `MainWindow` constructor sets `WindowState.Maximized` before the window is shown, so a change takes effect on the next start; the TUI has no such setting, as the terminal's window isn't its own), Panes (volume keys, Enter on file, copy limit, see [Temporary copies](volumes.md#temporary-copies), detecting images and archives, see [Detecting volume files](volumes.md#detecting-volume-files)), Columns (the columns of the left or right pane, chosen in a combo box, as check boxes in a list: checked ones are shown, Move up and Move down or Ctrl+Up/Down move the selected one, Reset shows the default ones; see [Pane columns](file-operations.md#pane-columns)), Copying (UAE metadata) and Editor (see [Editor settings](editor.md#settings)), and the button editor of a customizable theme after Appearance (see [Button editor](themes.md#button-editor)). Its tabs use the `SettingsTabItem` control theme instead of the Fluent theme's text headers, so they look like tabs (like the TUI's): bordered, the selected one with an accent line and joined to the bordered panel of its settings (drawn over the panel's border); the selected tab and the panel have the dialog's background, so only the borders mark them.
- Settings are stored in `~/.hst-commander/gui-settings.json`; a missing or invalid file gives defaults. The file has a format version and keeps settings it doesn't know (see [Settings files](application.md#settings-files)). The settings dialog previews theme changes live and reverts them on Cancel.
- The application icon is `src/icon/hst-commander.ico`, linked as `avares://Hst.Commander.Gui/Assets/hst-commander.ico`.
