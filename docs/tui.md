# TUI Front-End

The Terminal.Gui front-end (`Hst.Commander.Tui`). Read this when changing TUI behavior. What each feature does is in the feature docs; this covers how the TUI does it.

Paths are relative to `src/`. Part of the agent docs, see [`src/agents.md`](../src/agents.md).

## Files

- `MainWindow.cs`: the dual-pane window, its menus (File, Mark, Go, Commands, Help), columns, key bindings, theme colors and the handlers for every function key and dialog.
- `EntryTableView.cs`: the pane's `TableView`, with column dividers below the last entry and a scroll thumb.
- `PathPanelView.cs`: the panel above each pane (path, marked summary, disk space) and the pane's top border.
- `ListingProgressView.cs`: a framed spinner with "Reading ..." shown in the middle of a pane when listing it takes longer than `ListingProgress.Delay` (2 seconds), e.g. the physical disks while a sleeping disk wakes up, and, with a progress bar and a Cancel button, when making a temporary copy takes as long (the view is the pane's `NavigationContext.ProgressIndicator`; the table gets the focus back when it's hidden).
- `FunctionKeyBarView.cs`: the clickable function key bar. The title follows the key with no space (`F5Copy`, the key in its own color, like Midnight Commander), so the ten items of the main window fit in 80 columns.
- `TerminalScreen.cs`: the terminal output screen while the TUI is shut down, also running external editors (F4).
- `UnixTerminalKey.cs`: waits for a key on the output screen on Linux and macOS (see [Terminal programs](#terminal-programs)); `TerminalKeyPatterns.cs`: function key sequences Terminal.Gui doesn't know (see [Themes and settings](#themes-and-settings)).
- `TerminalProgressOutput.cs`: the progress of file operations in the terminal's tab or taskbar button, see [Terminals](#terminals).
- `TuiSettings.cs`, `TuiTheme.cs`, `TuiPalette.cs`: settings and the 16-color palette per theme; `TuiTrueColors.cs`: the RGB values of the 16 colors with true color.
- Dialogs, one file each: `ViewerDialog` (+ `ViewerView`, `ViewerSearchDialog`), `EditorDialog` (+ `EditorTextView`, `EditorSearchDialog`, `GoToLineDialog`), `SettingsDialog`, `CopyDialog`, `CopyProgressDialog`, `DeleteProgressDialog`, `MakeDirectoryDialog`, `CreateVolumeDialog`, `CreateVolumeFieldsDialog` (choices as a `ChoiceField`: a one-line drop-down opening its list in a popup, as Terminal.Gui's `ComboBox` needs room below it and changes the tab order), `SelectGroupDialog`, `PropertiesDialog` (a `Tabs` view with the General tab and the tabs of plugins as `PropertiesTabView`s; its separators are `Line`s drawing themselves, as a `Line` is otherwise drawn by its superview's line canvas, which `Tabs` draws over all tabs), `VolumeProviderDialog`, `BookmarksDialog` (the bookmark list of the Bookmarks item), `BookmarkDialog` (the description of a new bookmark), `EditBookmarkDialog` (the description, location, path, user name and stored password of a bookmark; invalid input shown below the fields), `LocationDialog`, `VolumeLocationDialog` (the location of a volume provider asking for one, e.g. an SMB path), `CredentialsDialog` (user name and password, the password hidden with `TextField.Secret`), `ConnectionDialog` (the protocol as an `OptionSelector`, host, port, path, user name and password of a volume provider asking for connection details, e.g. FTP/SFTP; invalid input shown in a label below the fields), `AboutDialog` (+ `LicenseDialog`, a read-only `TextView` with a license notice).

## Terminal.Gui

- Terminal.Gui **v2** (`2.5.0`). The API differs from v1 and from the v2 pre-alphas: consult the installed package (or its source at the matching tag), not online v1 docs. The TUI uses the static `Application` API (obsolete in 2.5, but still working) and imports Terminal.Gui's namespaces with global usings in the project file, aliasing `Attribute` and `Color`.
- Terminal.Gui 2.5 reads input on Windows as VT sequences, so mouse input arrives as SGR mouse sequences; tests writing to the console input buffer (`WriteConsoleInput`) send mouse clicks as such sequences.
- On Windows, Terminal.Gui's Windows driver may keep the console's line input mode on, and with it the console takes Ctrl+S as pausing the output instead of passing the key on (search, saving in the editor). `Program.cs` calls `TerminalScreen.DisableLineInput` after each `Application.Init`; Terminal.Gui reads key events and restores the original mode on shutdown.
- Colors: on Linux and macOS Terminal.Gui writes 24-bit colors, which terminals without true color ignore (e.g. Terminal.app before macOS 26 shows the TUI in monochrome). Unless `COLORTERM` is `truecolor` or `24bit` (`TerminalScreen.SupportsTrueColor`), `Program.cs` sets `Application.Driver.Force16Colors` after each `Application.Init` (which resets it), so the 16 standard colors of `TuiPalette` are written as such. On Windows, the Windows driver already uses 16 colors outside Windows Terminal. With true color (e.g. GNOME Terminal, Windows Terminal), the 16 colors are written with the RGB values of Windows Terminal's Campbell scheme (`TuiTrueColors`) instead of Terminal.Gui's, whose Gray (128,128,128) is barely lighter than DarkGray and made the cursor row, the active path and text fields very dark. They're set before any palette is created, because an attribute keeps the RGB values of its colors (a class of its own, as reading a static field of `TuiPalette` creates its palettes first), and after each `Application.Init`, because 16-color output looks up the nearest color in the same table.
- Pane keys are attached with `tableView.KeyDown += async (_, key) => { ... }`; there are no window-level key handlers. The panes handle F9 and F10 before the menu bar does.
- Dialogs derive from `TuiDialog` and add their buttons with `AddButton`, run with `Application.Run(dialog)`. Terminal.Gui 2.5's `Dialog` makes the last button added the default, leaves an empty row above the buttons (which are in the dialog's padding, below the content) and stops the dialog when Enter is pressed in e.g. a text field, before the default button handles it. `TuiDialog` keeps the button created with `IsDefault` as the default, puts the buttons right above the bottom border and leaves closing to the buttons' `Accepting` handlers (which set `e.Handled` and call `Application.RequestStop`), so a dialog checking its input or staying open (search) works with Enter. A dialog's `Result` property hides `Dialog.Result` (`new`).
- `TuiDialog` turns off the dialogs' shadow. Terminal.Gui 2.5's transparent shadow takes its colors from the screen under it (`ShadowView.GetAttributeUnderLocation`), which still holds the shadow of the previous frame when the views under the dialog aren't drawn again, so each redraw, e.g. each character typed in a text field, darkened it again and the shadow along the right and bottom border flickered (in 16 colors it alternated between black and dark gray).
- Message boxes are `TuiMessageBox.Query` and `ErrorQuery` (a `TuiDialog`), with the first button as the default and -1 when closed with Esc, as Terminal.Gui 2.5's `MessageBox` makes the last button the default.
- Schemes are made with `TuiPalette.CreateScheme`, setting every role Terminal.Gui 2.5 draws with: text fields (`Editable`) in the focus color and selected text and unfocused list selections (`Active`) in the focus color inverted, like earlier versions; the panes pass their normal color as `Active`, so a pane without focus doesn't show its cursor row. A text field selects its text when it gets the focus with the keyboard, so typing replaces it.
- Background work (copy, move, delete, counting, search) runs with `Task.Run` and reports with `UiThread.Post`, which queues an action that the main loop's `Iteration` event runs at the start of the next iteration, one at a time in order (only the actions queued before the iteration, so frequent progress reports taking long to draw can't keep the loop from handling keys, e.g. a Cancel button); an action showing a dialog runs the following ones in the dialog's loop. `UiThread` is also the UI thread's synchronization context, so `await` continues on the main loop through the same queue: `UiThread.Attach` (after each `Application.Init`) installs it and installs it again on `SessionBegun`, as each `Application.Run` installs Terminal.Gui's own.
- Terminal.Gui's `Application.AddTimeout` and `Application.Invoke` (also behind its synchronization context) aren't used from other threads: Terminal.Gui 2.5 holds the lock of its timeouts while running a timeout (`TimedEvents.RunTimers`), so when a timeout shows a dialog, e.g. an `await` continuing with `Application.Run` after a file read that completed asynchronously (as on Linux and macOS, or over SMB), adding a timeout from another thread waits until the dialog closes. That left the properties dialog at "Calculating..." for entries with an Amiga icon and on SMB shares, and the viewer at "Searching...". `Application.Invoke` also runs an action at once when called on the UI thread, so a dialog shown by it would run inside the caller (e.g. the main loop's error handler) and an exception would escape the caller instead of reaching the main loop's error handler. `UiThread.PostIfRunning` skips the action while the TUI is shut down (a program running in the terminal, Ctrl+O); it's used by the timer and callbacks that can fire then. Questions from a background operation (e.g. overwrite) are asked with `TuiMessageBox.Query` posted to the UI thread through a `TaskCompletionSource`. Cancel or Esc in a progress dialog cancels, and the dialog stays open until the operation has stopped.
- Errors are shown with `ErrorBox.Show(exception)` or `ErrorBox.Show(message, exception)`, which logs them (see [Errors and crash reports](application.md#errors-and-crash-reports)) and shows `TuiMessageBox.ErrorQuery`. Messages that aren't failures (invalid input, an action the location doesn't support) are shown with `ErrorBox.ShowNotice`, which isn't logged. Unhandled exceptions of the main loop are shown with `UnexpectedErrorDialog`.

## Panes

- Each pane is a private `Pane` class holding its `NavigationContext`, views, entries and `DataTable`. Its `EntryTableView` (like the search results) is a `CursorTableView`, which has the cursor's `SelectedRow` and `SelectedColumn` over Terminal.Gui 2.5's `TableView.Value` and raises `CellActivated` on Enter and double-click, handling the accept so Enter in a table in a dialog doesn't press the default button. The headers are drawn with `TableStyle.HeaderScheme`, as 2.5 draws them in the focus color otherwise.
- Names start with a marker character: the OS directory separator (`\` on Windows, `/` elsewhere) for directories (and `..`), `>` for files that can be opened as volumes (see [Detecting volume files](volumes.md#detecting-volume-files), unless detecting is turned off) and a space for other files. The marker is set when the file is detected after listing.
- The name column takes the remaining width; size and date columns shrink on narrow panes so everything fits. Long names are shortened with `~`, keeping the end of the stem and the extension when they fit. Sizes are humanized (`SizeFormatter.FormatEntrySize`): containers with a size, i.e. drives, partition tables and partitions, show it, other directories show `<DIR>`.
- The path panel highlights the path of the focused pane and trims it from the left with `...`; the disk space is dropped when the panel is too narrow.
- The cursor row is only drawn in the active pane (the pane last focused), so it stays visible while a dialog or the menu has the focus. Marked entries are yellow, also under the cursor.
- PageUp/PageDown move by a visible page; Ctrl+PageDown is checked before PageDown.
- **Quick search** (Ctrl+F, see [Quick search](file-operations.md#quick-search)): ` Find: text ` is a `Label` on the pane's bottom border (`Pane.QuickSearchLabel`, at `Pos.Left(bottomLine) + 1`, so it moves with the parent button), in the active path colors. While it's active, `HandleQuickSearchKey` gets the pane's keys first, comparing `KeyCode` (see the `Handled` note below). `EntryTableView.MousePressed` stops it on a click. The table's `CollectionNavigator` is null, because Terminal.Gui's type-ahead matched the marker character at the start of each name.
- Ctrl+R (Go > Refresh) lists the active pane again. Ctrl+U (Go > Swap panes) swaps the `Pane` objects and their views' `X` and `Width` (`PlacePaneView`: the left pane is half the width rounded down and the right pane fills the rest, so an odd width leaves no empty column at the right edge), so each pane moves to the other side with its location, entries, marks and cursor; the active pane stays active, so the focus moves to the other side.
- Ctrl+H (Go > Home directory) goes to the home directory. Terminals and the Windows console send it as the control character `0x08`, which Terminal.Gui decodes as Ctrl+Backspace, so that goes home too. Terminals sending Backspace as `0x08` can't tell the two apart, so there Backspace may go home instead of to the parent; most send `0x7F`. Go > Home directory and Home in the location dialog always work.
- Typing `/` or `\` goes to the root of the volume, like Ctrl+\ (`IsGoRootKey`). The typed characters work with every keyboard layout and terminal, while terminals can't send Ctrl+\ on layouts without a `\` key (e.g. Danish, where it's AltGr+<, or macOS). Terminals send Ctrl+\ as `0x1C`, which Terminal.Gui decodes as Ctrl+4; on Windows, Ctrl+< (the key left of Z) works too.
- Ctrl+\ arrives as the control character `0x1C`, which is also sent for Ctrl+4, so both match. The Windows driver decodes Ctrl with the key's character in the current layout, so Ctrl+`<` matches too: the key left of Z is `<` on e.g. Danish and German layouts.
- Terminal.Gui's `Key` equality includes `Handled`, so a handler comparing `key == Key.X.WithCtrl` after setting `key.Handled = true` never matches; compare before, or compare `KeyCode` (Ctrl+X once copied instead of cutting this way).
- Ctrl+P is the main properties key (shown in the menu), because Windows Terminal and the classic console use Alt+Enter for full screen; Alt+Enter still works where the terminal passes it on.
- **Context menu:** right-clicking a row (`EntryTableView.RightClicked` on `RightButtonClicked`) makes it the current entry and shows a Terminal.Gui `PopoverMenu` (registered with `Application.Popovers`) at the mouse with Copy, Cut, Paste, Rename, Delete, PowerShell here, Terminal here, Command prompt here and Properties, like the GUI; items that don't apply are disabled. Shift+F10 or Ctrl+F10 shows it below the current entry (handled in the pane's `KeyDown` before F10, which quits); Ctrl+F10 for terminals taking Shift+F10 for their own context menu, e.g. GNOME Terminal. The shell items (`ShellHere` in Core, only Terminal here on macOS and Linux) open the shell in a new window in the pane's directory when it's local, like the GUI. Ctrl+C, Ctrl+X, Ctrl+V, Alt+V and Shift+F6 are handled in the pane's `KeyDown` (Shift+F6 before F6); the menu shows Alt+V for Paste, as Windows Terminal and the classic console take Ctrl+V for pasting text. A `System.Threading.Timer` checking on the main loop through `UiThread.PostIfRunning` lists the panes again when cut files were moved by another application (`EntryClipboard.CheckCutMoved`). The clipboard of the operating system is only used on Windows (see [Clipboard](file-operations.md#clipboard)).
- No drag and drop: terminals can't drag files out and only some type a dropped file's path (see [Drag and drop](gui.md#drag-and-drop) in the GUI).
- The volume provider list is centered over its pane. It and the create volume list (F9) have OK and Cancel buttons like the GUI. Enter in the list is handled in the list's `KeyDown` and chooses the selected item, as do OK and double-click.

## Viewer

`ViewerView` draws in the pane colors (offsets in the header color, the match in the cursor color, the selection in the dialog focus color). Selecting with the mouse uses `MousePositionTracking` and `Application.Mouse.GrabMouse` while dragging. Copying uses `Clipboard.TrySetClipboardData`, and the status line says when the terminal doesn't support it. No image view.

## Themes and Settings

- Themes: Midnight Commander (default), Light and Dark, from `TuiPalette`, plus the themes of plugins with the closest of the 16 colors (`TuiPalette.From`, see [Themes](themes.md)). `MainWindow.ApplyTheme` reapplies them, including the buttons of the bottom area (`ButtonPanelView`, the function key bar for the built-in themes, as high as its tallest column) and the parent buttons (`ParentStripView`). The settings dialog previews theme changes live and reverts them on Cancel.
- Message boxes (`TuiMessageBox`) use Terminal.Gui's global "Dialog" and "Error" schemes, whose focused button barely differs from the others (dark gray instead of black text), so the focus seemed stuck, and the menus of the menu bar and the context menu are popovers with the global "Menu" scheme. `MainWindow.ApplyMessageBoxColors` sets them to `TuiPalette.DialogColorScheme`, `ErrorColorScheme` and `MenuColorScheme` and gives menus a single-line border (`MenuSettings.Current`, also set before the menu bar is created, as a menu gets its border when created), on theme changes and on `Application.InitializedChanged`, because `Application.Init` reloads Terminal.Gui's configuration and resets them.
- The settings dialog groups the settings in a `Tabs` view (a tab is a view with a `Title`): Appearance (theme), Panes (volume keys, Enter on file, copy limit, see [Temporary copies](volumes.md#temporary-copies), detecting images and archives, see [Detecting volume files](volumes.md#detecting-volume-files)), Copying (UAE metadata) and Editor (see [Editor settings](editor.md#settings)), and the button editor of a customizable theme last (see [Button editor](themes.md#button-editor)). Its option selectors have `MouseHighlightStates = MouseState.None`: Terminal.Gui saved a view's color scheme when it was pressed and set it as the view's own when released, so a clicked option selector would keep the previous theme's colors instead of inheriting the dialog's previewed theme. Arrow keys move the cursor in an option selector, and Space or a click selects.
- **Function keys Terminal.Gui doesn't know:** Terminal.Gui 2.5's `CsiKeyPattern` matches every `ESC [ code ~` sequence but throws a `NullReferenceException` for codes it doesn't map (e.g. Ctrl+F10 in Terminal.app). `TerminalKeyPatterns.Install` (after each `Application.Init`) adds `ExtraFunctionKeyPattern` before Terminal.Gui's patterns, changing the private pattern list of the driver's keyboard parser (nothing is changed when it isn't found). It maps the VT220 codes of F13 to F20 (25, 26, 28, 29, 31, 32, 33, 34) to shifted function keys, Shift+F5 to Shift+F12 in Terminal.app (`TERM_PROGRAM` is `Apple_Terminal`) and Shift+F3 to Shift+F10 as in rxvt elsewhere, so Shift+F10 opens the context menu and Shift+F6 renames in Terminal.app; other unknown codes are no key.
- Settings are stored in `~/.hst-commander/tui-settings.json`; a missing or invalid file gives defaults. The file has a format version and keeps settings it doesn't know (see [Settings files](application.md#settings-files)).

## Terminal Programs

- Programs that run in the terminal (`FileStarter.IsTerminalProgram`: console-subsystem `.exe` by PE header, `.com`, `.bat`, `.cmd` on Windows; files with execute permission elsewhere) suspend the TUI like Midnight Commander. `MainWindow.StartFile` stores a `TerminalAction.RunProgram` and stops the window.
- `Program.cs` loops: `TerminalScreen.EnterTui`, `Application.Init`, `Application.Run(mainWindow)` (whose `IsRunningChanged` lists both panes at the same time and draws the window again when each is listed, so a pane waiting for a sleeping disk doesn't keep the other blank: `UiThread.Attach` installs the synchronization context of the main loop, so awaiting a listing that isn't done at once, like the physical disks, before the main loop runs would hang with a blank screen), `Application.Shutdown`, `TerminalScreen.LeaveTui`, then runs the pending terminal action (none when quitting) and shows the same `MainWindow` again. Errors starting a program are shown once the window is loaded again. Other files, including GUI programs on Windows, are started with the shell without suspending.
- Ctrl+B adds a bookmark (`BookmarkDialog`); the Bookmarks item of `VolumeProviderDialog` opens `BookmarksDialog` (or a message when there are no bookmarks), where Del deletes and F4 (or F2) edits the selected bookmark (`EditBookmarkDialog`).
- Ctrl+O (`TerminalAction.ShowOutput`) shows the output screen until a key is pressed. On Linux and macOS the key is read with `UnixTerminalKey` (turning off line input and echo with `tcsetattr` while waiting, then restoring the settings), as in the external editors' "Press a key", not with `Console.ReadKey`: once .NET's console has configured the terminal for reading keys, it gives each program started afterwards the settings it saved while Terminal.Gui had the terminal in raw mode, so a command run after Ctrl+O printed its lines without returning to the first column (each line indented further) and ignored Ctrl+C.
- Commands typed in the command line run the same way with `TerminalAction.RunCommand` (see [Command line](command-line.md#tui)).
- Windows Terminal and Unix terminals draw the TUI on the alternate screen, so the output survives. The classic Windows console doesn't, so `EnterTui` gives the TUI a screen buffer of its own there and `LeaveTui` restores the original, which is also needed because Terminal.Gui's `WindowsConsole.Cleanup` activates a new empty buffer on shutdown. Windows Terminal is detected by `WT_SESSION` or a pseudo console window (`PseudoConsoleWindow`): a program started as administrator, e.g. when restarting as administrator, doesn't get `WT_SESSION` but is shown in Windows Terminal when it's the default terminal, and a screen buffer of its own is never shown there, leaving the screen blank.
- In Windows Terminal, switching the active screen buffer makes the pseudo console repaint the visible screen. Terminal.Gui's `WindowsConsole.Cleanup` switches to a new, empty buffer on shutdown, so leaving the TUI (e.g. for Ctrl+O or a command) painted the screen with spaces, hiding the last screen of output behind empty lines; captured from Windows Terminal's `OpenConsole.exe`. So `TerminalScreen.BeforeShutdown` (called before `Application.Shutdown`) does the cleanup itself there with reflection, restoring the console mode and cursor and stopping reading input without switching, and removes the console from the driver, which then only leaves the alternate screen; `LeaveTui` then doesn't switch back. When Terminal.Gui's internals differ, the driver cleans up as before.

## Terminals

- From Windows, run the TUI on a remote machine with the Windows OpenSSH client (`ssh`) in Windows Terminal; it's the tested route. SSH usually doesn't pass on `COLORTERM`, so the TUI uses 16 colors there (see [Terminal.Gui](#terminalgui)).
- Terminal.app on macOS needs keyboard settings for Shift+F1/Shift+F2 and for marking with Shift+Up/Shift+Down, as it doesn't send these keys by default; see [macOS Terminal](volumes.md#macos-terminal).
- PuTTY isn't supported, and there's no code for it: it sends `TERM=xterm` like other terminals, and only its answerback to ENQ identifies it.
  - F1-F4 don't work with PuTTY's default keyboard setting, which sends `ESC[11~` to `ESC[14~` instead of xterm's `ESC OP` to `ESC OS` that Terminal.Gui reads. Set Terminal > Keyboard > "The Function keys and keypad" to Xterm R6.
  - Some controls show black text on a black background in PuTTY; the cause isn't known yet.
- The copy, move and delete progress dialogs show their progress in the terminal's tab or taskbar button (see [Common rules](file-operations.md#common-rules)) with the ConEmu escape sequence `ESC ] 9 ; 4 ; state ; percent BEL` (`TerminalProgress`), written to the standard output by `TerminalProgressOutput` on the UI thread, where Terminal.Gui draws too. It's only written to terminals known to show it (`TerminalProgress.IsSupported`): Windows Terminal (`TerminalScreen.IsWindowsTerminal`), ConEmu (`ConEmuANSI=ON`), WezTerm and Ghostty (`TERM_PROGRAM`) and iTerm2 3.6 or later (`TERM_PROGRAM_VERSION`), because other terminals, e.g. older iTerm2, show any `OSC 9` as a desktop notification. Over SSH `TERM_PROGRAM` usually isn't passed on, so nothing is shown there.
